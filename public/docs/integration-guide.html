Integration Guide

Recommended integration sequence for checkout/address forms.

Recommended Flow

  1. User types street/area text.
  2. Call GET /search to populate suggestions.
  3. User selects a suggestion.
  4. Auto-fill postcode, area, LGA, state.
  5. Optional: Use location and call POST /reverse-geocode.

Data Contract

  • houseNumber
  • street
  • postcode
  • postcodePrefix
  • area
  • lga
  • state
  • lat / lng (optional)

Minimal Browser Example

async function searchAddresses(query) {
  const res = await fetch(`/search?query=${encodeURIComponent(query)}&limit=10`);
  if (!res.ok) throw new Error(`Search failed: ${res.status}`);
  const data = await res.json();
  return data.results;
}

function applySelection(record, form) {
  form.street.value = record.street;
  form.postcode.value = record.postcode || `${record.postcodePrefix}000`;
  form.area.value = record.area;
  form.lga.value = record.lga;
  form.state.value = record.state;
}

Pilot Caveats

  • Lagos-only dataset in current MVP.
  • Many records have postcode: null; fallback to prefix.
  • Reverse geocode is centroid-backed; treat as assisted suggestion.
  • Keep manual override for support operations.

Production Hardening

  • Add API key and rate limits before public exposure.
  • Cache common search/postcode lookups.
  • Track unresolved addresses for data quality cleanup.
  • Add schema validation for API responses in client apps.
